## 2. 主线和记录约定

1. 主算法入口是 `run_algorithm.py --algorithm tg-mappo`，原环境位于 `src/buoy_network/environment.py`。
2. `run_research.py`、`reference_grid` 和研究 Graph-MAPPO 保留作参考工具。它们的训练结果不能记成原 TG-MAPPO 的实验结果。
3. 开始时先检查代码是否有新增修改、解释器是否正确，再读取上一次实验日志。结束时写清“做到哪、结果在哪、还差什么、下一次做什么”。
4. 每次按“函数 → 模块 → 联调”验证相关改动，小步推进；不要把一次短启动或负向检查通过写成完整功能已实现。
5. 实验使用新输出目录，保留历史 CSV、配置、日志和模型。每次记录完整命令、随机种子、代码版本/改动、实际训练预算及退出情况。
6. 若修复改变环境、观测、动作、奖励或指标定义，要给同一修正规则下的所有组重跑基线；修复收益不能记成 WM/PM 收益。
7. 新模块先匹配当前 TG-MAPPO 的实际信息范围。是否限制为局部观测要单独设计，并对所有对照组一致执行。
8. Python/GPU 环境迁移单独验证、单独记录；GPU 可用性不作为当前 CPU 接口整理的前置条件。

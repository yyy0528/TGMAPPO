# PM独立校准门控：定点修复与新种子开发实验

日期：2026-11-05。原TG-MAPPO、原浮标环境、Python3.6.8 / Torch1.8.1 CPU。

## 问题与修复范围

上一轮任务回报PM的三个种子为0/20/16包，平均投递率仍25%，效果失败。GAE计算已核对，不能继续把下降简单归为GAE公式错误。确认的设计缺口是：离线验证合格后，PM固定按alpha=1使用，没有针对当前策略初始化检查其价值先验是否可靠。

本轮增加**独立初始价值校准门控**。校准单独采集任务，在PPO前完成并冻结；之后重置RNG、重新构造初始策略，使用新训练轨迹。门控只决定alpha=0或1，不修改Actor动作、基础奖励或PM权重。

这修复的是“不可靠先验仍无条件启用”的接口缺口。初始价值校准不是完整不确定性模型，也不保证训练后路由更好；效果另行验收。

## 输入、输出和规则

每个初始化使用两个独立校准场景，每场景2×80时隙，共4任务、320时隙。Actor为未训练初始化策略，采用原掩码下的采样动作；全程禁用GAE/PPO，检查Actor/Critic指纹不变、优化器状态为空。

每步保存原尺度初始Critic值V0、环境奖励r_env、PM任务回报势Phi。完整任务结束后只在校准阶段计算采样MC回报G。每个任务的比较是：

```text
e_base = mean((V0 - G)^2)
e_PM   = mean((V0 + maximum_alpha*Phi - G)^2)
```

每个任务内按时隙/节点平均，再对任务等权平均。这些节点副本和相邻前缀高度相关，不能当成额外独立重复。

预定规则：4任务中每个e_PM都小于e_base，且整体MSE至少降低5%，才接受PM；否则alpha=0。规则在运行前写入代码/配置，不使用路由评估分数或逐种子硬编码。

校准标签使用完整回报是明确的监督阶段。**同一条PPO轨迹不得在执行后才回看未来结果来选择自己的奖励权重**。本实现先完成所有校准、固定alpha，再启动新的PPO采样，保持训练期间势函数/alpha冻结。

## 实现和保护

- `src/buoy_network/pm_reliability.py`：校准打分、固定门控、报告重算和契约核对。
- `src/buoy_network/pm_calibration.py`：原环境的未训练策略采样与只读缓存；自带禁止PPO/GAE的断言。
- `scripts/calibrate_tg_pm.py`：生成包含原始校准数组、初始化指纹和门控决定的独立报告。
- `FrozenPMRuntime`接收`--pm_reliability_report`；`requested_alpha`记录上限，`alpha`记录实际值。校准文件、规则、初始策略签名、PM版本、奖励契约、gamma均绑定。训练初始化不匹配、报告被改动或加载另一门控版本会拒绝。
- 新接口仅用于无WM的feedforward `task_return / learned_shaped`。旧模式和默认PM关闭均保留。
- 门控拒绝时，PPO参数应精确等于无PM；接受时应精确等于始终启用PM。它不是额外Actor网络，也不是根据评估分数事后挑选checkpoint。

## 新种子实验协议与当前状态

配置：`configs/tg_pm_reliability_pilot.json`。训练种子44/55/66，校准场景4101/4102，开发评估8101/8102/8103，三者互不重叠。三个组为原TG、始终PM、校准PM；各训练20×80、PPO1×2、每网络40步Adam，固定学习率、Critic时钟关闭、5移动节点和随机信道，Actor/Critic容量保持一致。

校准额外960时隙在三个初始化间独立，在同一初始化的各组间共享，所有组均记录/计入这项成本。主要对照相同PPO阶段预算，**尚不能证明计入全部校准成本后的样本效率优势**；若有收益还需要原TG多训练4回合的总交互成本对照。

运行目录：`results/tg_pm_reliability/20261105_152508_334744`。先完成全部校准，再开始任何PPO任务；完整计划3个校准进程、9个训练、27个冻结评估，共39任务。三个新种子校准均选择alpha=1，因此门控与始终PM等价；不能声称本批已经展示拒绝不可靠预测的收益。

效果门槛在配置中预定：校准PM均值同时超过原TG与始终PM，至少2/3种子比原TG好，任何种子不低于原TG，且基础折扣回报均值更高。保持该门槛，结果未齐时不宣布通过。即使通过也只属于开发证据。

另对旧失败种子11做独立校准定点回归，明确不混入新种子主表。首次命令误用了猜测的历史目录，在采集前即失败/交互0；已记录`regression_path_failure.json`，改从manifest读取真实目录，没有重复训练。修正后校准MSE 0.382030→0.064244，仍选择alpha=1；**这个代理指标没有识别已知的贪心零投递失败，不能称为有效的路由可靠性门控**。

新种子44已完成：原TG每场景6/48，始终PM与门控PM均0/48，且两个PM模型参数和物理轨迹精确相同。该工程分支一致性通过，但结果不能作为稳定性修复通过。

另对旧失败策略11做160时隙只读采样回放，PPO0更新/权重不变，采样送达18/48，而原贪心为0/48。18次Sink ACK成功中5次标准化GAE为负；但Sink动作平均优势仍高于其他合法动作，不能说奖励把Sink全部反向训练。各节点值/优势差异约1e-7，表明使用的是接近共同的团队信号，未实现节点级因果归因。这是方差/贪心排序问题的线索，不是GAE公式错误证明。产物`.../sink_credit_seed11/sink_credit.json`。

因此门控保留为明确标注的实验接口，不推广。随后单独检查原方案7.4/参数表建议的alpha=0.1冷启动；此前各次实际使用alpha=1。新对照仅改变alpha，沿用上一轮task_return的归档源码、种子11/22/33、20回合及8001/8002/8003开发场景，旧基线/alpha=1结果只读复用。配置`configs/tg_pm_strength_probe.json`，目录`results/tg_pm_strength/20261105_154758_858806`。没有把调低强度预先写成有效修复，也不把这些开发场景再次当作盲测。

两个实验均已结束并完成独立审计：[强度修正与最终结果](TG_MAPPO_PM_STRENGTH_FIX.md)。门控均值16.67%低于原TG的25.93%，效果失败；低强度均值27.78%高于原TG25%，恢复seed11，但seed22仍退化，稳定收益门槛失败。不能把门控或低强度说成已稳定修复全部问题。
